What is measured

  • wall ms is the whole client process: reading the source, parsing it, connecting, and doing the work.
  • µs per round trip is wall ms divided by the round trips — the number a person means by latency.
  • MB/s counts both directions, because every byte is sent and comes back.
  • Each row is the middle of the runs, not the fastest: a loopback benchmark on a busy machine has occasional slow runs and no occasional fast ones.

What is not measured

Not the kernel's TCP. Loopback is the fastest and least interesting network there is. The numbers are about the interpreter: how much work stands between a program saying net_send and the bytes leaving the process. The Go rows are the control for that — the same work, same machine, no interpreter.

When the network costs something

Loopback is the one network on which the interpreter's share of a round trip is large, and the one on which it does not matter to anybody. The latency sweep asks the other question: the same two clients, the same exchange, against a server that waits before it answers, so that a round trip costs what a real one costs.
